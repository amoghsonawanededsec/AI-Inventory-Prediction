MASTER BUILD PROMPT — AI-POWERED SMART INVENTORY MANAGEMENT & WASTE REDUCTION

Build a production-style, full-fledged web application titled:
“AI-Powered Inventory Demand Forecasting, Waste Reduction and Intelligent Conversational Decision Support System”.

Use the attached project specification as the source of truth for the functional scope. The system must combine inventory management, ML demand forecasting, waste/expiry prediction, reorder optimization, analytics, and an intelligent chatbot. The attached specification explicitly describes React/HTML/CSS frontend options, Python FastAPI/Flask backend, PostgreSQL/MySQL/MongoDB, ML with Pandas/NumPy/scikit-learn/XGBoost/TensorFlow/PyTorch, and chatbot capabilities including NLP, LLM, RAG, embeddings and vector search.

PRIMARY GOAL
Create a complete usable product, not a demo page. All major screens must be connected to a real backend/API and database, with seeded sample data. Avoid hard-coded dashboard numbers where a database/API calculation is expected.

TECHNOLOGY
- Frontend: React + TypeScript + Tailwind CSS.
- Backend: Python + FastAPI.
- Database: PostgreSQL with SQLAlchemy/SQLModel and migrations.
- ML: Pandas, NumPy, scikit-learn; XGBoost for a strong tabular forecasting baseline; support a time-series model such as LSTM/GRU or ARIMA as an experimental option.
- Chatbot: intent detection + tool/function calling + RAG. Use an LLM provider through an environment variable. Do not expose API keys in frontend code.
- Vector store: use a simple local/vector implementation for development and make the interface replaceable by pgvector/another vector DB.
- Authentication: JWT with role-based access control.
- Deployment: Docker + docker-compose; include .env.example and production configuration guidance.
- Charts: Recharts or equivalent.

USER ROLES
1. Admin
   - Manage users, products, suppliers and system settings.
   - View organization-wide analytics.
2. Inventory Manager
   - Add/update products, monitor stock, view predictions, approve purchase recommendations.
3. Staff
   - Record sales and stock updates.
   - Ask chatbot questions.
Enforce permissions in the backend, not only the UI.

E. Demand Forecasting
Create a forecasting pipeline:
1. Validate/clean historical data.
2. Engineer lag, rolling mean, day-of-week, month, season, holiday,
   promotion, price and inventory features.
3. Split train/validation/test chronologically.
4. Train at least two models, e.g. Random Forest/XGBoost and a time-series model.
5. Compare MAE, RMSE, MAPE and R² where applicable.
6. Select the best model per configured strategy.
7. Store forecasts in the database.
8. Expose forecast APIs and visualization.
Allow forecast horizons such as 7, 14 and 30 days.
Clearly distinguish actuals from forecasts.

F. Waste Prediction
Estimate potential surplus/waste using:
current stock, forecast demand over remaining shelf life, expiry date,
average sales velocity and product characteristics.
Classify:
- LOW
- MEDIUM
- HIGH
Show estimated units at risk and estimated monetary value.
Provide recommended actions:
discount, promote, transfer, stop ordering, prioritize selling, donate if eligible.

G. Expiry Detection
Automatically identify:
- expired
- expiring within 1 day
- within 3 days
- within 7 days
Provide alerts and action recommendations.
Never claim a product is expired unless the expiry date is actually past.

H. Smart Reorder Recommendation
Calculate:
recommended_order =
max(0, forecast_demand_during_lead_time + safety_stock - current_stock)
Optionally account for maximum stock and minimum order quantity.
Show:
- current stock
- reorder point
- forecast demand
- safety stock
- supplier lead time
- recommended quantity
- explanation
Require manager approval before generating a purchase order.

I. Purchase Orders

J. Supplier Management

CHATBOT ARCHITECTURE
User → Web Chat UI → Chat API → authentication/context → intent/router →
tools (inventory DB, analytics queries, forecast service, waste service,
reorder service) + RAG retrieval → LLM response.

The chatbot must NOT invent database values. For quantitative questions,
retrieve live data through backend tools. For document/policy questions,
use RAG and cite the retrieved source title/section in the response.
Return structured tool results internally, then generate a concise natural-language answer.

Implement chatbot intents such as:
inventory_status, low_stock, forecast, expiry, waste_risk,
reorder, sales_analytics, revenue, supplier, explanation, what_if,
general_inventory_help.
